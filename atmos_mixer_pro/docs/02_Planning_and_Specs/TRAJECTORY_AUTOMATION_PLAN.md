# Spatial Trajectory & Automation 기획서

## 1. 개요 (Overview)
본 기획은 Atmos Mixer Pro에서 정적인 소리 배치를 넘어, **시간의 흐름에 따라 가상 소리 객체(Virtual Source)가 3D 공간을 이동하는 궤적(Trajectory) 오토메이션**을 구현하기 위한 설계 문서입니다. 전시/테마파크 환경에서 외부 OSC 신호를 받아 오디오 재생과 동시에 공간 이동 효과(예: 등 뒤에서 머리 위를 지나 앞으로 날아가는 포탄 소리)를 완벽하게 동기화하여 재생하는 것을 목표로 합니다.

---

## 2. 핵심 워크플로우 (Core Workflow)

1. **디자인 (Design):** 사용자가 3D 캔버스에서 특정 사운드 트랙(SFX)의 시작점, 경유지, 도착점을 클릭하여 3D 이동 경로를 그립니다.
2. **설정 (Config):** 해당 경로를 이동하는 총 소요 시간(Duration)과 곡선 형태(Curve)를 설정합니다.
3. **대기 (Standby):** 엔진이 설정값을 메모리에 로드하고 자체 플레이어의 재생 대기 상태로 들어갑니다.
4. **트리거 (Trigger):** 우리 프로그램 내의 대시보드 UI에서 `[▶️ Play]` 버튼을 누르거나 단축키를 입력합니다. (필요 시에만 외부 OSC 신호를 받습니다).
5. **실행 (Execution):** Rust 오디오 엔진이 자체 내장된 Player로 `.wav` 파일을 재생함과 동시에 0.0초부터 타임라인을 가동하여, 매 샘플마다 DBAP 좌표를 갱신하며 스피커 볼륨을 실시간으로 패닝(이동) 시킵니다.

---

## 3. 프론트엔드 UI/UX 기획 (Flutter & Three.js)

### A. 3D 캔버스 'Trajectory Mode' (궤적 그리기 모드)
*   **모드 전환:** 캔버스 툴바에 `[ ✍️ Draw Path ]` 버튼을 추가하여 궤적 편집 모드로 진입합니다.
*   **노드(Node) 생성:** 3D 공간 상에 클릭하여 **시작점(Start)**, **경유지(Waypoints)**, **도착점(End)** 생성합니다. (로직 프로의 3D Panner에 시간 개념을 더한 형태)
*   **시각화:** 노드들을 잇는 선형(Linear) 또는 부드러운 곡선(Spline/Bezier)이 3D 공간에 시각적으로 표시됩니다. 플레이 헤드(가상의 소리 위치)가 애니메이션으로 선을 따라 움직이는 프리뷰(Preview) 기능을 제공합니다.

### B. Track Inspector (궤적 디테일 설정 패널)
궤적이 적용된 트랙을 선택하면 우측 인스펙터 패널에 다음 옵션이 노출됩니다.
*   **Total Duration:** 이동에 걸리는 총 시간 (예: `3.0` 초). 오디오 파일의 원래 길이에 맞추거나 커스텀 설정 가능.
*   **Curve Type:** `Linear`(직선 이동), `Smooth`(부드러운 곡선), `Ease In/Out`(출발/도착 시 가감속).
*   **Loop Mode:** `One-shot`(1회 재생 후 멈춤), `Loop`(반복 회전), `Ping-pong`(왕복).

## 4. 백엔드 아키텍처 기획 (Rust DSP 엔진)

### A. Trajectory 연산 엔진 (`trajectory.rs` 신설)
단순히 시작/끝 좌표를 던져주는 것을 넘어, Rust 오디오 스레드 내에서 작동하는 매우 가벼운 보간(Interpolation) 엔진이 필요합니다.
*   **Keyframe 구조체:** `[Time Ratio (0.0~1.0), Vector3 (X,Y,Z)]` 형태의 키프레임 배열을 메모리에 캐싱.
*   **Real-time Interpolation:** 오디오 버퍼(Buffer)를 채우는 매 순간, 경과된 시간을 계산하여 현재 소리의 정확한 (X, Y, Z) 좌표를 도출합니다.

### B. 재생 동기화 (`player.rs` + `dbap.rs`)
*   트랙 재생이 시작되면 자체 내부 타이머(오디오 샘플 기반 카운터로 지연/오차 0%)가 작동합니다.
*   계산된 현재 (X, Y, Z) 좌표를 기존에 개발된 DBAP 알고리즘에 즉시 전달합니다.
*   DBAP는 그 좌표에 맞춰 각 스피커(ch1~6)의 타겟 Gain을 계산하고, 이전 작업에서 적용한 Gain Smoothing(지퍼 노이즈 방지)을 거쳐 최종 출력됩니다.

## 5. OSC 제어 및 통합 (OSC Integration)

전시장 시스템과의 통합을 위해 고도화된 OSC API를 노출합니다.

*   `/track/1/play` : 1번 트랙 오디오 재생 및 궤적 오토메이션 동시 시작.
*   `/track/1/stop` : 재생 및 이동 즉시 정지.
*   `/track/1/reset` : 소리 위치를 궤적의 시작점(T=0)으로 강제 초기화.
*   (선택) `/track/1/pos x y z` : 오토메이션이 없는 트랙의 경우, 외부 OSC에서 실시간으로 좌표를 쏴서 직접 이동시키는 모드(Live Tracking).

## 6. 예상되는 기술적 챌린지 및 해결 방안

1.  **Audio-Visual 동기화 오차:**
    *   *문제:* 화면에 보이는 소리 궤적 UI 애니메이션과 실제 스피커에서 나는 소리의 위치 간에 딜레이가 발생할 수 있습니다.
    *   *해결:* 시계(Timer)의 마스터 주도권을 Flutter(UI)가 아닌 **Rust Audio Thread(샘플 단위)**에 두고, Rust가 "나 지금 이 위치 재생 중이야"라는 진행률(Progress) 데이터를 UI로 올려주는 방식을 채택합니다.
2.  **부드러운 커브 이동 시 CPU 부하:**
    *   *문제:* 복잡한 3D Bezier Curve 수학 연산을 오디오 스레드(Per-sample)에서 실시간으로 처리하면 틱(Tick) 노이즈가 발생할 수 있습니다.
    *   *해결:* 궤적 곡선 계산은 설정(Apply) 버튼을 누를 때 1024개 등의 세밀한 선형 좌표 리스트(Lookup Table)로 사전 계산(Pre-compute)하여 Rust 엔진에 전달합니다. 오디오 스레드는 배열에서 값을 읽어오기만 하므로(O(1) 비용) 부하가 제로에 가깝습니다.
