# 무음·꺼진 채널의 리미터 건너뛰기 설계

- 작성: 2026-11-27, Windows Main
- 근거: HANDOFF 남은 일 16 "그 뒤 후보 — 꺼진 채널의 리미터 우회(먼저 '채널을 다시 켤 때 클릭' 시험을 지금 코드에 만들고 시작)", 사용자 결정 2026-11-27(1.3.21 뒤 세 후보를 모두 하되 현장은 안정 운영)
- 상태: 구현·이 PC 빌드·테스트 끝(2026-11-28, 브랜치 `win/limiter-silence-skip`). 범위는 리미터만(사용자 "권장대로 리미터부터"). 장치 확인(4절 6번)은 남음. 측정·구현 결과는 6·7절.

## 1. 목적

열린 채널이 많을 때(64~94채널) 소리가 나지 않는 채널의 피크 리미터 계산을 건너뛰어, 콜백 처리 시간을 줄인다. **소리는 한 샘플도 바뀌지 않아야 한다.**

- 지금 측정값
  - 현장 12채널 처리: 평균 3.0~3.3ms/블록(예산 21.3ms)
  - 출력 설정이 비어 94채널을 모두 처리했을 때: 16~17ms(2026-11-2x R3 보완 기록, 예산 초과)
  - 64채널 WAV 재생: 평균 10~11ms(2026-11-24)
- 채널당 약 0.15ms/블록이 든다. 그 안에서 리미터가 얼마인지는 아직 재지 않았다(→ 4절 1단계).

## 2. 지금 동작(`rust/src/audio/mixer.rs`, `audio/limiter.rs`, main 13c5933)

- 처리 폭(`out_channels`) = 출력 설정이 여는 가장 높은 채널이다. 그 안의 닫힌 채널(게이트 0)도 채널 DSP와 리미터를 계속 돈다.
  - 1.3.16(#137) 결정 "닫힌 채널도 DSP 유지": 다시 열 때 필터·잔향 상태가 끊기지 않게 하려는 것이다.
- 출력 단계에서 채널마다 프레임마다 `limiters[ch].process(val)`을 부른다.
- `PeakLimiter::process` 한 번에 하는 일
  - 4배 Hermite 보간으로 샘플 사이 피크를 찾는다.
  - 엔벨로프 2개(빠름·느림)를 4번 갱신하고 hold 카운터를 센다.
  - 무릎 게인을 계산하고, 게인 리덕션 텔레메트리를 남긴다(`gain < 1`이면 `log10`).
  - 5ms 지연 줄을 읽고 쓰고, 0.985 안전 클립을 건다.
  - 3초 LUFS 창 합을 갱신하고 128번에 한 번 `log10`을 한다.
- 입력이 0이어도 이 일을 모두 한다.

## 3. 바꿀 동작

### 3.1 건너뛰는 조건(블록 단위, 채널마다)

다음이 모두 참이면 그 블록에서 그 채널의 `process()`를 부르지 않는다.

1. 이 블록에서 리미터에 들어갈 값(헤드룸을 곱한 뒤)이 모두 0이다. 닫힌 채널의 잔향 꼬리가 아직 남아 있으면 0이 아니므로 그대로 처리한다.
2. 리미터가 비었다: 지연 줄이 모두 0이다. 이는 마지막으로 0이 아닌 표본을 넣은 뒤 지연 줄 길이(5ms) 넘게 0만 넣었다는 뜻이고, 카운터 하나로 센다.
3. 게인 리덕션이 없다: 두 엔벨로프가 모두 무릎 아래(`knee_lower`)다. 이때 `process()`의 게인은 1이고 출력은 지연된 0이다.

이 조건에서 `process()`를 불렀다면 출력은 0이고, 바뀌는 상태는 아래뿐이다. 이를 O(1)로 그대로 맞춘다.

### 3.2 건너뛸 때 상태를 똑같이 맞추기(정확히 같은 결과)

0을 N번 넣었을 때 바뀌는 상태만 같은 연산으로 맞춘다. 4배 검출이라 엔벨로프 갱신은 4N번이다.

- **느린 엔벨로프**: 입력 0이면 `coef × (env − 0) + 0` = `env × coef`다. 표본마다 4번 `slow_envelope *= slow_release_coef`.
- **빠른 엔벨로프**: hold 카운터가 남은 동안은 그대로(카운터만 1씩 줄임)이고, 그 뒤 `fast_release_coef`를 곱한다. 역시 4번씩.
- 처음 설계는 `coef^(4N)`을 `powi` 한 번으로 구하려 했다. 반복 곱과 반올림이 달라(1024프레임 블록에서 상태 상대 약 1e-5, 출력 최대 2.4e-7) 2026-11-28 코드 리뷰 뒤 반복 곱으로 바꿨다. 이제 상태가 비트까지 같다. 곱셈 몇 번이라 `process()`(보간·지연 줄·무릎 게인·클립)보다 훨씬 싸다.
- **history** 3칸: 0으로 둔다.
- **지연 줄**: 모두 0이라 회전 위치와 상관없이 같다. `delay_index`는 그대로 두어도 출력이 같다.
- **게인 리덕션 텔레메트리**: 0 dB를 쓴다(`process()`도 게인 1이면 0을 쓴다).
- **LUFS 창**: 0을 N개 넣는 것과 같게, 합에서 빠져나가는 값만 빼고 칸을 0으로 채운다. 간단한 루프라 `process()`보다 훨씬 싸다.
  - 128번마다 하는 `log10`도 같은 자리에서 한다.
  - 마스터 LUFS는 `limiters[0]`(CH1)만 읽지만, 모든 채널에 같은 규칙을 쓴다.
- 결과: 출력·VU·LUFS·게인 리덕션이 늘 `process()`를 부를 때와 정확히 같다(0과 −0은 같은 값으로 본다). 시험도 정확히 같은지를 본다.

### 3.3 건드리지 않는 것

- 채널 DSP(딜레이·EQ·게인·극성·초기반사·리버브 센드), 베이스 매니지먼트 크로스오버, 바이노럴은 그대로 돈다(#137 결정 유지).
  - 1단계 측정에서 리미터보다 이쪽이 훨씬 크면, "무음 채널 DSP 건너뛰기"를 따로 설계한다. DSP는 잔향 꼬리 상태가 있어 더 어렵다.
- 리미터를 끈 설정(`peak_limiter_enabled = false`)의 안전 클램프 경로
- 처리 폭 계산, 채널 게이트 10ms 램프

## 4. 순서(시험 먼저)

1. **측정**: `bin/route_bench`와 같은 방식으로 94채널 믹서의 블록 시간을 잰다. 리미터 켬과 끔을 비교해 리미터 몫을 구하고, 같은 방식으로 채널 DSP와 크로스오버 몫도 잰다. Release 빌드로 5회.
   - 리미터 몫이 작으면(예: 블록의 10% 미만) 이 설계는 보류하고 결과만 기록한다.
2. **"다시 켤 때 딸깍" 시험**(지금 코드에서 통과해야 함)
   - 사인을 내는 채널을 출력 설정에서 끈다(게이트 10ms 램프 → 0). 몇 블록 뒤 다시 켠다.
   - 다시 켜는 구간의 샘플 간 최대 변화가 정상 사인의 최대 변화를 넘지 않는다(1.3.16 `channel_gate` 시험과 같은 판정).
3. **같은 결과 시험**(건너뛰기 전후 비교)
   - 같은 입력에 대해 늘 `process()`를 부르는 기준 리미터와 건너뛰는 리미터의 출력이 같다.
   - 입력 시나리오: 무음 블록 사이의 짧은 소리, 큰 소리(게인 리덕션 중) 뒤 바로 무음, 5ms보다 짧은 무음, 긴 무음 뒤 큰 소리
   - 2번 시험의 끄고 켜기 흐름도 포함한다.
   - 이 시험은 구현 전에는 건너뛰는 경로가 없어 실패해야 한다.
4. **구현**: `PeakLimiter`에 `zero_run`(연속 0 개수)과 `skip_silent_block(n)`(3.2의 O(1) 전진)을 둔다. 믹서 출력 단계는 블록마다 3.1 조건을 보고 건너뛴다. 할당·잠금 없음(3법칙). `test_audio_thread_no_heap`에 경우를 더한다.
5. **다시 측정**: 1번과 같은 조건. 현장처럼 12채널만 소리 나고 82채널이 무음일 때의 블록 시간을 줄이는 것이 목표다.
6. **장치 확인**
   - 현장 프로젝트 30분: 부하 비교, 같은 소리(사람)
   - 94채널을 열고 12채널만 재생: 부하 비교
   - 채널을 끄고 켤 때 딸깍 없음(사람)
7. **문서**: HANDOFF, 현장 점검표 12절(94채널 부하)
