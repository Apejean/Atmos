# 출력 설정 = 줄마다 따로, Ableton처럼(짧은 설계)

> 상태: **사용자 결정(2026-11-22 "이전처럼 에이블톤처럼 따로 하자 파일 문제도 고쳐", 설계 설명 뒤 "응 그렇게 진행해"), Windows Main 작성.** 1.3.15·1.3.16의 `2026-11-21-output-config-open-channels-design.md`(세 줄을 열린 채널 하나로 묶기)를 이 문서로 바꾼다. 트랙 자리 판단은 같은 날 먼저 정한 `2026-11-21-track-route-must-match-group-design.md`(A, 종류가 맞아야 소리)로 돌아가고, 멀티 줄이 여는 채널만 새로 정한다. 경로는 `atmos_mixer_pro/` 기준.

## 왜
- 1.3.16 설치본 확인(2026-11-22 00:59) 중 사용자가 물었다: Ableton은 Output Config의 모노·스테레오를 따로 켜고 끄지 않는가. Ableton에서 출력 설정은 트랙 출력 목록에 무엇을 띄울지 정하고, 모노 7·8만 켜거나 스테레오 쌍만 켤 수 있다(포럼 확인, 설명서는 "모노·스테레오 쌍 중 어떤 것으로 쓸지 정한다"까지).
- 같은 확인에서 묶기의 결함이 나왔다: 모노 CH2를 껐다 켜면 모노 CH2만 다시 켜지고 스테레오 1/2·멀티 CH2 시작은 파일에 꺼진 채 남았다. 창은 열린 채널로 세 줄을 그려 켜져 보였다(창과 파일이 어긋남).

## 규칙
- **Output Config 창:** 줄을 누르면 그 줄만 켜지고 꺼진다(`core/utils/output_channel_toggle.dart` `setOutputRow`). 창은 각 줄의 저장된 `enabled`를 그대로 보인다 — 보이는 것이 파일과 같다. 켜고 끌 때 이름·지연·EQ·위상·게인·위치는 그대로 둔다(2026-11-21 고친 것 유지).
- **트랙이 소리를 내는 조건(A와 같다):** 자리 종류는 파일 채널 수와 `output_stereo`로 정한다(`required_group`: 3채널 이상 → 멀티, 모노 파일 → 모노, 스테레오 파일 → 스테레오 출력이면 스테레오·아니면 모노). 그 종류의 줄이 켜져 있어야 한다: 모노 자리 CHk → 모노 줄 k, 스테레오 자리 CHk/k+1(짝 1/2·3/4…) → 스테레오 줄 k, 멀티 자리 CHk → 멀티 줄 k. 맞지 않으면 10ms에 걸쳐 무음, 재생 위치는 흐른다(`SoundInstance.route_gain`), 트랙 카드는 "CH n (출력 설정에 없음)"을 주황으로 보인다.
- **트랙 출력 목록:** 파일 종류에 맞는 켠 줄만 나온다(`channel_routing.dart` `buildChannelRoutingItems`). 켠 줄이 없으면 비어 있다(2026-11-21 "아무것도 안 켜면 소리 없음" 그대로).
- **채널 게이트(어느 장치 채널로 내보내는가):** 켠 줄이 닿는 채널의 합. 모노 k → CHk, 스테레오 k → CHk·CHk+1, **멀티 k → CHk부터 그 자리를 쓰는 다채널 트랙(스테레오 출력 켬)의 가장 긴 파일 채널 수만큼**, 그 자리 트랙이 없거나 모노로 합치는 트랙뿐이면 CHk 하나. 그래서 멀티 CH1 시작만 켜도 24채널 파일이 CH1~24로 나간다(스테레오 1/2만 켜도 CH1·CH2로 나가는 것과 같다). 1.3.14까지는 멀티 k가 장치 끝까지 열었고, 1.3.15·1.3.16은 CHk 하나만 열었다.
- **처리 폭:** 채널 게이트의 가장 높은 채널(`processing_channel_count`). 파일 채널 수는 메모리에 읽은 음원이면 그 값, 아니면 머리말을 읽어 경로·크기·수정 시각으로 기억한다(`output_groups::cached_file_channels`, 오디오 스레드 밖). 트랙의 파일·출력이 바뀌어 폭이 달라지면 출력 설정을 바꿀 때처럼 엔진이 한 번 다시 시작한다.

## 엔진
- `GLOBAL_STATE.{mono,stereo,multi}_rows_open`(원자형 4096개, 0부터 센 시작 채널)을 설정을 읽거나 바꿀 때 `apply_enabled_channels`가 채운다(`output_groups::apply_row_tables`). 설정을 읽기 전 기본값은 채널 게이트처럼 모두 열림.
- 믹서는 블록마다 인스턴스의 자리를 줄 표로 본다(`route_open`, 할당·잠금 없음). 믹서 코드는 바뀌지 않는다.

## 파일 문제와 옮기기
- 창과 파일이 같아져 "창에는 켜져 보이는데 파일에는 꺼진 줄"이 새로 생기지 않는다.
- 자동으로 고치지 않는다: 1.3.15·1.3.16에서 저장한 공연에는 창에 켜져 보였지만 파일에는 꺼진 스테레오·멀티 줄이 있을 수 있다. 새 버전은 꺼진 그대로 보이고, 그 줄을 쓰는 트랙에 주황 안내가 뜬다(릴리스 노트·Mac에 알림). 어느 줄을 사용자가 일부러 껐는지 파일로는 가릴 수 없다.
- 이 PC 현장 공연: 2026-11-22 CH2 시험으로 스테레오 1/2·멀티 CH2 시작이 꺼졌다. 그대로면 CH1/2 스테레오 트랙 3개가 무음이 되므로, 새 버전 설치 때 앱을 닫은 상태에서 시험 전 백업(`D:\dev\backups\20261122-005727-before-1316-install`)대로 되돌린다(사용자 확인 2026-11-22).

## 남은 것
- (고침 2026-11-22, 사용자 "8,9번은 지금 진행") 스테레오·멀티 줄을 새로 켜면 그 채널의 모노 보정값(지연·EQ·위상·게인·위치)이 기본값으로 덮였다 — 엔진 시작(`AudioMixer::new`)·설정 불러오기(`api_get_config`)·튜닝 동기화(`syncFromBackendConfig`)가 모노 → 스테레오 → 멀티 순서로 덮어 적용했다. 이제 멀티 → 스테레오 → 모노 순서라 그 채널의 모노 줄 값이 이기고, 모노 줄이 없는 채널만 스테레오·멀티 값을 쓴다. 튜닝 창의 스테레오 링크 스위치도 동기화가 줄 종류로 다시 정하지 않는다(`tests/test_channel_calibration_mono_first.rs`, `test/tuning_sync_mono_first_test.dart`).
- (고침 2026-11-22) 모노 파일은 자기 채널 CHk 하나로만 나간다. 예전에는 스테레오 출력 표시가 남은 모노 파일(새 트랙 기본값)을 믹서가 CHk+1에도 올려 내, CHk+1이 다른 줄로 열려 있으면 거기로도 소리가 났다(트랙 카드가 화면에 뜨면 표시를 모노로 고쳤지만 카드를 그리기 전에는 샜다). 업믹스를 없앴다(`tests/test_mono_file_own_channel.rs`, 이전 `test_mono_to_stereo_upmix.rs`).
