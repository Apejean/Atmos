# 출력 설정이 비었을 때 믹서 처리 폭(짧은 설계)

> 상태: **사용자 결정(2026-11-20 "1번 설계대로 고쳐"), Windows Main 작성.** 경로는 `atmos_mixer_pro/` 기준.

## 왜
1.3.13 설치본 확인(2026-11-20)에서 출력 설정(모노·스테레오·멀티 그룹)이 빈 시험 프로젝트를 열자 믹서가 장치 전체 94채널을 처리했다(`core/processing_channels.rs` "켠 그룹이 없으면 장치 전체"). 처리 부하가 평균 2.9ms → 16~17ms, 최대 28ms(예산 21.3ms), 10초에 예산 초과 최대 23회 — 소리가 끊길 수 있다. 현장에서도 출력 설정이 빈 프로젝트를 열면 같은 일이 생긴다.

## 바꾸는 것(켠 그룹이 하나도 없을 때만)
- 처리 폭 = 아래 둘 중 큰 값(장치 채널 수를 넘지 않음, 최소 2):
  1. **트랙이 쓰는 가장 높은 채널**: 모든 방의 모든 트랙에 대해 `output_channel`(0부터 센 장치 채널, CH1 = 0) + 폭. 폭은 믹서 규칙 그대로(`audio/mixer.rs` 846~912행) — `output_stereo`가 꺼져 있으면 1(다채널도 모노로 합침), 켜져 있으면 파일 채널 수(모노 파일이면 2: 모노→스테레오 올림).
  2. **서브우퍼 채널**: 스피커 배치에서 서브로 지정한 가장 높은 채널(베이스 매니지먼트가 저역을 그 채널로 보낸다 — 트랙이 없는 채널이어도 소리가 나간다).
- 파일 채널 수는 미리 읽은 음원(`preloaded_sounds`)이면 그 값, 아니면 파일 머리말(symphonia probe)로 읽고 경로·크기·수정 시각으로 기억한다. 읽지 못하는 파일은 어차피 재생되지 않으므로 계산에서 빼고 앱 로그에 한 번 남긴다.
- 켠 그룹이 있으면 지금 규칙 그대로(이 PC 현장 설정 CH1~12 → 12채널). `compute_enabled_channels`(어느 채널로 소리가 나가는가)는 바꾸지 않는다 — 폭만 줄인다.

## 다시 계산하는 때
- 엔진 시작(`audio/engine.rs`), 설정이 바뀔 때(`api/simple.rs` `request_restart_if_processing_width_changed`), 스피커 배치가 바뀔 때(`api_update_spatial_config_json` — 서브 채널이 바뀌면). 폭이 바뀌면 지금처럼 엔진을 다시 연다(멈춘 위치부터 이어 감).
- 알려진 한계: 앱 시작 때 스피커 배치는 엔진이 열린 뒤 화면이 보내므로, 서브가 트랙보다 높은 채널에 있고 출력 설정이 빈 프로젝트면 시작 직후 한 번 다시 열 수 있다(짧은 끊김). 출력 설정이 있는 프로젝트는 해당 없음.

## 하지 않는 것
- 멀티 그룹만 켜졌을 때 "장치 끝까지"(파일 채널 수를 모름) 규칙은 그대로 둔다(따로 판단).
- 채널 게이트·라우팅·매트릭스 라우팅 설계는 건드리지 않는다.

## 1.3.15 수정(2026-11-21, 1.3.14 설치본 확인에서 발견, 사용자 결정 "지금 고치고 1.3.15")
- **맨 위 채널 하나를 빠뜨림**: 1.3.14는 `output_channel`을 1부터 센다고 보고 `output_channel + 폭 − 1`로 계산했다. 실제로는 0부터 센다(Dart `TrackConfig.outputChannel`, 믹서 `hw_ch = output_channel + ch`; Rust `TrackConfig` 주석 "1 to 24 (1-indexed)"가 틀려 있었다). 그래서 CH25·26 스테레오 트랙이 있는 출력 설정 빈 공연에서 25채널만 처리해 CH26이 무음이었다(믹서 최소 16채널 위에서만 드러남, CH1에서 시작하는 트랙은 우연히 맞음). 이제 `output_channel + 폭`.
- **출력 설정 저장 한 번에 엔진 재시작 두 번**: 저장하면 설정이 여러 번 들어오고, 옛 엔진을 내리는 사이(처리 폭 값이 아직 옛 값) 들어온 설정이 재시작 요청을 다시 남겨 새 엔진이 뜨자마자 한 번 더 재시작했다(1.3.14 확인 12:28·12:31, 짧은 끊김 두 번). 이제 처리 폭 재시작 요청은 장치 유실 신호(`device_needs_reset`)와 따로 두고(`GLOBAL_STATE.processing_width_restart`), 엔진 관리 스레드가 요청을 꺼낼 때 지금 연 믹서 폭과 원하는 폭을 다시 비교해 같으면 건너뛴다(`processing_channels::take_width_restart_request`, 정지 이유 `processing_width_changed`).

## 시험
- 순수 함수 `used_channel_ceiling`(트랙 번호는 0부터): 모노 트랙 CH5 → 5, 모노 파일 스테레오 출력 CH5 → 6, 24채널 파일 N:N CH1 → 24, 다채널 파일 모노 합침 CH7 → 7, 읽지 못하는 파일은 빼기, 서브 CH40 → 40, 장치 채널로 자름, 아무것도 없으면 2.
- `effective_processing_channels`: 켠 그룹이 없으면 위 값, 있으면 기존 규칙.
- 실기: 출력 설정이 빈 7번 시험 프로젝트 → 시작 로그 "94채널 중 24채널 처리", 부하 경고 없음.
