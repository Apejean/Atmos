# 출력 설정 = 열린 채널 하나(짧은 설계)

> **대체됨(2026-11-22).** 1.3.16 설치본 확인 중 사용자가 "이전처럼 에이블톤처럼 따로 하자"를 골라 `2026-11-22-output-config-separate-rows-design.md`로 바뀌었다. 세 줄은 다시 따로 켜고 끄며, 트랙은 자기 종류의 줄이 켜져 있어야 소리를 낸다. 이 문서는 1.3.15·1.3.16의 동작 기록이다.

> 상태: **사용자 결정(2026-11-21 "채널 하나로 묶기", 예시로 다시 설명한 뒤 "응 진행해"), Windows Main 작성.** 구현: `rust/src/core/output_groups.rs`(`open_channels`·`route_open`), `compute_enabled_channels`·`processing_channel_count`가 그것을 씀, 믹서 `SoundInstance.route_gain`, Dart `channel_routing.dart` `openOutputChannels`, `core/utils/output_channel_toggle.dart`(창 켜고 끄기). 경로는 `atmos_mixer_pro/` 기준. 1.3.15 범위(브랜치 `win/width-zero-based`). 같은 날의 `2026-11-21-track-route-must-match-group-design.md`(종류가 맞아야 소리, A)를 이 문서로 바꾼다 — "화면에 안내가 뜨는 트랙은 무음"은 그대로이고, 기준이 "그룹 종류"에서 "열린 채널"로 바뀐다.

## 왜
A 장치 확인(2026-11-21 15:52) 중 사용자가 "스테레오 1/2를 켜면 모노 1·2랑 멀티 시작 1·2도 켜져야 하고, 모노를 켜도 스테레오·멀티가 그만큼 켜지고, 멀티를 켜도 마찬가지"라고 했다. 출력 설정의 모노·스테레오·멀티 세 줄을 따로 켜는 지금 방식은, 같은 채널을 열었는데도 트랙 종류에 따라 고를 수 없거나 소리가 나지 않는다.

## 규칙
열린 채널 C(0부터) = 켠 모노 k → {k-1} ∪ 켠 스테레오 k → {k-1, k} ∪ 켠 멀티 k → {k-1}.
- **멀티 k는 시작 채널 하나만 연다**(지금은 k부터 장치 끝까지 연다 — 바뀌는 점). 다채널 파일은 시작 자리가 열려 있으면 고를 수 있고, 파일의 각 채널은 열린 채널로만 나간다.
- 화면 세 줄은 C를 보여 준다: 모노 k = CHk 열림, 스테레오 k/k+1(지금처럼 1/2·3/4… 짝) = 두 채널 모두 열림, 멀티 k 시작 = CHk 열림.
- 트랙 출력 목록·엔진이 소리를 내는 조건(맞는 자리)도 C로 본다: 모노 자리 c = c 열림, 스테레오 자리 c(짝 시작) = c·c+1 열림, 멀티 자리 c = c 열림. 파일 채널 수별 자리 종류(다채널 → 멀티, 모노 → 모노, 스테레오 → 스테레오 출력이면 스테레오·아니면 모노)는 A와 같다. 맞지 않으면 무음(10ms 페이드, 위치는 흐름).
- 처리 폭 = C의 가장 높은 채널(장치 안). 켠 것이 없으면 0. "멀티가 맨 위면 장치 끝까지" 규칙은 없어진다.

## 화면 Output Config 창
- 줄을 켜면 그 줄의 채널을 연다: 닫혀 있던 채널마다 **모노 항목**을 켠다(없으면 만든다).
- 줄을 끄면 그 줄의 채널을 닫는다: 그 채널을 덮는 모든 항목(모노·스테레오·멀티)을 끄고, 꺼진 항목이 덮던 나머지 채널은 열린 채로 두기 위해 모노 항목을 켠다.
- 왜 모노 항목만 만드는가: 항목마다 채널 DSP 설정(지연·EQ·위상·게인·위치)이 있고, 엔진은 켜짐과 상관없이 모노 → 스테레오 → 멀티(6채널) 순서로 덮어 적용한다(`audio/mixer.rs` `AudioMixer::new`·공간 재계산). 스테레오·멀티 항목을 새로 만들면 기존 보정값을 기본값으로 덮는다. 모노는 가장 먼저 적용되어 새로 만들어도 기존 값에 영향이 없다.
- 함께 고치는 것: 지금 줄을 누르면 `ChannelSetting`을 새로 만들며 위상 반전·게인을 기본값으로 되돌리고 위치를 지운다(`_buildChannelRow`). 켜고 끌 때 다른 값은 그대로 둔다.
- `config.json` 구조는 바꾸지 않는다(세 맵 그대로).

## 바꾸는 곳
- Rust: `compute_enabled_channels`(멀티는 시작 채널만), `processing_channel_count`(C의 최댓값), `core/output_groups.rs` `route_open`(종류별 표 대신 `enabled_channels`로 판단, 스테레오는 짝 시작). A에서 넣은 종류별 표(`{mono,stereo,multi}_group_open`, `group_start_tables`)는 뺀다.
- Dart: `channel_routing.dart`에 C 계산·항목 생성(C 기준), Output Config 창의 표시·켜고 끄기(순수 함수로 빼서 시험).
- 사용자 실제 공연(백업): 모노 1~12·스테레오 1,3,…,11·멀티 1,2 → C = CH1~12. 다채널 트랙(4채널, CH1)은 CH1~4로 그대로 나간다. 지금은 멀티 1이 CH1~94를 열고 있지만 CH13 이상으로 가는 트랙이 없어 들리는 소리는 같다.

## 시험
- Rust: 게이트(멀티 k는 k 하나), 처리 폭(C 최댓값), `route_open`(종류·짝·열림), 믹서(맞지 않으면 무음·위치 흐름·딸깍 없음 — A 시험을 C 기준으로).
- Dart: C 계산, 목록 생성, Output Config 켜고 끄기(모노 항목만 만들기, 끌 때 다른 채널 유지, 다른 DSP 값 보존).
- 장치: 스테레오 1/2만 켜면 모노 1·2·멀티 1·2도 켜져 보이고, LONG(24채널, CH1)은 CH1~2로만 소리. CH23~24를 더 켜면 CH23~24도.
